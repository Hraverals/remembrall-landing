■ 이 장의 역할 - 기술 강조점 2: OS 지오펜스 개수 제한을 '재조회(resync)' 구조로 해결 ■ 화면 구성 - 왼쪽 도식: 점선 큰 원 = 재조회 원, 작은 원 = 저장 장소(반경 150m), 가운데 점 = 현재 위치 - 오른쪽: OS 한도 막대(iOS 20 / Android 100), 해결 방식, 기각한 대안 4개 ■ 문제 - 앱당 지오펜스 한도: iOS 20개, Android 100개 → 저장 장소 전체 등록 불가 ■ 해결 (ADR003) - 현재 위치 기준 가까운 순으로 (한도 − 1)곳 등록: iOS 19 / Android 99 - 남은 한 자리 = 재조회 원. 반경 = max(3km, 가장 먼 등록 장소 + 500m), 중심 = 현재 위치 - 재조회 원 안의 장소는 전부 등록된 상태 → 원을 벗어나는 순간 서버에 다시 물어 목록 교체 - 지역을 미리 나눌 필요 없음, Android/iOS 같은 로직 - 서버: 현재 위치 기준 하버사인 거리로 가까운 순 조회(PostgreSQL 내장 함수, PostGIS 미사용) ■ 기각한 대안 - 지역+장소 2단계 등록: 지역 지오펜스가 슬롯을 차지 - iOS 큰 위치 변경 감지(significant location change): Expo에서 사용 가능 여부 불확실, 플랫폼 분기 - Android DWELL(30초 머무름): 걸어서 지나가는 경우를 거의 못 거름 - 주기적 위치 폴링: iOS가 백그라운드 실행을 보장하지 않음, 배터리 ■ 세부 동작 - 서버에는 두 플랫폼 모두 ENTER(진입)만 보냄. 장소 EXIT는 앱 상태 초기화에만, 재조회 원은 EXIT만 사용 - 재등록 시점: 앱 시작, 포그라운드 복귀, 저장·삭제 후, 재조회 원 이탈, 위치 설정 변경 - 재부팅·앱 업데이트 후 자동 복원 - 장소별 안/밖 상태를 파일에 기억 → 집 근처 장소 때문에 앱을 열 때마다 알림이 가는 것 방지(Android는 등록 시 초기 ENTER가 오는데 이미 안이면 무시) - 도착 보고 큐: 최대 20건, 시간 예산 12초, 실패 시 같은 이벤트 ID로 재전송 - 서버는 에이전트 판단과 FCM 전송까지 끝낸 뒤 202 응답(동기). 앱은 10초 타임아웃 후 같은 이벤트 ID로 재전송, 서버는 같은 이벤트 중복 실행을 막음 ■ 알려진 한계 (Notion: 자체 인지) - Android는 스쳐 지나가도 ENTER 발생 → 2시간 쿨다운을 소모해 이후 실제 방문 알림이 막힐 수 있음 - 위치 껐다 켜기·강제 종료·앱 데이터 삭제 후에는 앱을 다시 열 때까지 지오펜스가 비어 있음 - 재부팅 시 등록 소실 → 자동 복원 + 재동기화로 복구 - 앱이 꺼진 상태에서 동작하려면 '항상 허용' 필수 - 현재 빌드는 Android 전용(iOS 한도까지 설계만 맞춤) ■ 시연 팁 - 모의 위치 앱은 Fused Location Provider 모의 모드를 쓰는 앱이어야 지오펜스에 반영, 삼성폰은 배터리 백그라운드 제한 확인 ■ 시간 - 약 45초
