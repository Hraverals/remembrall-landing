주기적 폴링

[시간] 약 45초 [대본] 두 번째는 지오펜스입니다. 휴대폰 OS는 앱 하나가 등록할 수 있는 지오펜스 수를 제한합니다. iOS는 20개, Android는 100개입니다. 저장한 장소가 수백 곳이 되면 전부 등록할 수 없습니다. 그래서 현재 위치에서 가까운 순서로 한도보다 하나 적게만 등록하고, 남은 한 자리에 그림의 점선 같은 큰 원, '재조회 원'을 등록합니다. 사용자가 이 원 밖으로 나가면 서버에 다시 물어서 새 위치 기준으로 목록을 갈아끼웁니다. 덕분에 지역을 미리 나눌 필요가 없고, 안드로이드와 iOS가 같은 로직으로 동작합니다. 지역 2단계 등록, iOS 큰 위치 변경 감지, 안드로이드 DWELL, 주기적 폴링도 검토했지만, 플랫폼마다 분기가 필요하거나 비용이 커서 기각했습니다. [세부 사실 — 질문 대비] - 장소 반경 150m. 재조회 원 반경 = 가장 먼 등록 장소까지 거리 + 500m(최소 3km). 실제 등록 수 iOS 19 / Android 99 + 재조회 원 1. - 서버: PostGIS로 가까운 순 N개 조회(GET /api/geofences). - 앱: expo-location + expo-task-manager. 장소별 안/밖 상태를 기억해 반복 보고 방지. 등록 시점에 이미 반경 안이면 거리 직접 계산. - 도착 보고는 큐 + 같은 이벤트 ID로 재시도(최대 20개, 30분 지난 이벤트 폐기). 서버는 항상 202 즉시 응답 → 결과는 FCM. [알려진 한계 — 스스로 인지하고 있음을 보여주면 좋음] - Android는 스쳐 지나가도 이벤트가 발생할 수 있음 → 쿨다운 소모(서버 2시간 쿨다운 + 에이전트 침묵 판단으로 과잉 알림 억제). - 재부팅 시 OS 등록이 사라짐 → 부팅 시 마지막 목록 자동 재등록 + 재동기화. - 현재 빌드는 Android 전용. iOS 한도까지 설계만 맞춰 둔 상태.
