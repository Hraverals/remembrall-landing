■ 이 장의 역할 - Q&A 뒤 부록. "데이터는 어떻게 저장하나" 질문이 나오면 넘겨서 보여주는 용도. 본편에서는 넘기지 않음 ■ 관계 (테크스펙 ER) - member 1 — 0..1 device (회원당 기기 1대 전제, 세션 토큰은 해시만 저장) - member 1 — n member_consent (활성 동의는 회원·유형별 하나: 위치기반서비스 / 공용 후보 기여) - member 1 — n personal_save n — 1 content (같은 영상은 content 하나를 여러 회원이 공유) - content 1 — n content_place n — 1 place (저장물 하나에 장소 여러 개 연결 가능) - content 1 — n confirm_candidate (되묻기 후보) - member × place → trigger (회원별 장소 트리거, 지오펜스 등록 단위) - trigger 1 — n recall_execution 1 — n recall_execution_trace (실행 단계 기록: 후보 검토 → 도구 호출 → 결과 → 판단 변경) - recall_execution 1 — 0..1 notification (실행당 알림 최대 1개) - business_license: 지방행정인허가 데이터 적재분. 공공 상가정보에 없는 프랜차이즈 보완 ■ 설계 포인트 - place는 검증 제공자 + 제공자 장소 ID로 고유. 카카오 이름·주소는 저장하지 않고 ID만 - 좌표에는 UNIQUE를 걸지 않음(같은 건물에 여러 장소). 내부 식별자는 자체 UUID라 제공사를 바꿔도 됨 - content.embedding은 768차원 벡터(pgvector). 임베딩 실패해도 분석 결과는 저장하고 벡터만 비움 - 멱등 키: content.video_id, personal_save(member, content), recall_execution(trigger, trigger_event_id), notification.execution_id - 원시 추론·정확한 현재 좌표는 저장하지 않음. trace에는 단계와 결과만
