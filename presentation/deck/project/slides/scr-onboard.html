■ 이 장의 역할 - 위치 '항상 허용'이 필요한 앱이 권한을 어떻게 설득하며 받는지 ■ 화면 구성 - 시작(00a) → 알림(00c) → 위치 ①(00d, 앱 사용 중) → 위치 정보 동의 시트(자두색) → 위치 ②(00e, 항상 허용) → 첫 저장 안내(00f) → 근처 탭 ■ 왜 이렇게 나눴나 - 앱을 닫아도 근처 도착을 알려면 위치 '항상 허용' 필수 - 처음부터 '항상 허용'을 요구하면 대부분 거절 → 이유를 먼저 보여주고 두 단계로 받음 - '앱 사용 중' 권한 없이는 '항상 허용'을 받을 수 없음 → 00d를 건너뛰면 00e도 건너뜀 - Google Play 정책상 백그라운드 위치는 사용 전 고지가 필요 → 00d·00e가 그 역할 - "나중에 할게요"를 눌러도 앱은 사용 가능, 설정에서 다시 켤 수 있음. '앱 사용 중'까지만이면 근처 알림만 꺼짐 ■ 화면 문구 - 00a "저장만 해두고 잊은 곳, 근처에 가면 다시 꺼내드릴게요" - 00c "근처에 가면 알려드릴게요 / 자주 울리지 않게 조용히 보낼게요." - 00d "위치는 저장한 곳 근처에 왔는지 확인할 때만 써요. 두 단계로 허용해요." - 00e "마지막으로 '항상 허용'이 필요해요" - 00f "Shorts에서 공유하면 여기에 쌓여요" ■ 위치 정보 이용 동의 시트 (위치기반서비스 약관) - OS 권한과 별도로 명시적 동의를 받음 - 3줄 약속: · "저장한 곳 근처에 왔는지만 확인해요 / 도착하면 그 장소와 시각만 서버로 보내요" · "지나온 길은 남기지 않아요 / 이동 경로나 실시간 위치는 보내지 않아요" · "언제든 거둘 수 있어요" - 같은 시트를 온보딩·근처 탭(위치 꺼짐)·설정 세 곳에서 재사용 - 동의 → 서버 기록 → 그다음 OS 권한 요청. 저장 실패 시 권한 요청으로 넘어가지 않음 - 약관 버전이 바뀌면 동의 없음과 똑같이 취급하고 재동의("위치 정보 약관이 바뀌었어요") - 철회 시: 앱이 지오펜스 전부 해제, 서버는 위치 이벤트를 실행 없이 버림. 문구 "거두면 저장한 곳 근처에 와도 알려드리지 않아요. 저장한 기억은 그대로 남아요." - 동의·철회 시각은 멱등(첫 시각 유지) ■ 로그인 - MVP는 게스트 세션: 설치 ID(보안 난수, 기기 보안 저장소)로 조용히 발급 → 로그인 화면 생략 - 세션이 끊기면 조용히 다시 받고 원래 요청을 한 번 재전송 - 한계: 앱 데이터 삭제·재설치 시 새 게스트가 되어 이전 저장물 접근 불가 → 카카오 로그인(구조 준비 완료)으로 해결 예정 ■ 시간 - 약 30초
